# Local Smart Card Bridge Contract

## ขอบเขต

เว็บ Clinic HIS ไม่เข้าถึง USB, PC/SC, driver หรือข้อมูลในบัตรประชาชนโดยตรง เนื่องจากเบราว์เซอร์ไม่ควรมีสิทธิ์ดังกล่าว ระบบจึงใช้ **Local Smart Card Bridge** ที่คลินิกติดตั้งและดูแลบนเครื่อง Front Desk เป็นจุดเชื่อมต่อแยกต่างหาก โดยเว็บเรียกใช้เฉพาะหลังผู้ช่วยคลินิกกดปุ่ม `อ่าน Smart Card` เท่านั้น

Bridge ต้องไม่ส่งภาพบัตร, ที่อยู่, วันเกิด, ชื่อ หรือข้อมูลไฟล์ใดจากบัตรมายังเว็บแอป สำหรับ workflow ปัจจุบัน Bridge ส่งได้เฉพาะเลขประจำตัวประชาชน 13 หลักตามสัญญาต่อไปนี้

```ts
window.clinicSmartCardBridge = {
  readNationalId: async (): Promise<{ nationalId: string }> => ({ nationalId: "<13-digit-national-id>" }),
};
```

## ข้อกำหนดด้านความปลอดภัย

| หัวข้อ | ข้อกำหนด |
|---|---|
| การเปิดใช้ | Bridge ต้องอนุญาตเฉพาะ origin ของ Clinic HIS ที่กำหนดโดยคลินิก และปฏิเสธ origin อื่น |
| การยืนยันผู้ใช้ | ต้องเรียกได้เมื่อผู้ช่วยกดปุ่มบนหน้า Front Desk เท่านั้น ไม่รองรับการอ่านอัตโนมัติเมื่อเปิดหน้า |
| ข้อมูลตอบกลับ | ต้องตอบเฉพาะ `nationalId` เป็นสตริงตัวเลข 13 หลัก ห้ามส่งข้อมูลอื่นของบัตร |
| การส่งต่อ | ตัว Bridge ต้องไม่ส่งเลขบัตรออกสู่อินเทอร์เน็ตหรือเก็บ log ที่เป็นเลขเต็ม |
| ความล้มเหลว | หากไม่พบ reader, ไม่มีบัตร, PIN/driver มีปัญหา หรือ Bridge ไม่พร้อม ต้องคืน error แบบทั่วไปและให้ผู้ช่วยกรอกเอง |
| การบันทึก | Server จะตรวจ checksum, เข้ารหัส, สร้าง lookup hash, บันทึก audit และล็อก write-once เอง ไม่เชื่อค่าใดจาก Bridge นอกเหนือจากเลขบัตร |

## ลำดับการใช้งาน

1. ผู้ช่วยคลินิกค้นหาและเลือก HN ที่ถูกต้อง
2. ผู้ช่วยกด `อ่าน Smart Card` หรือกรอกเลขด้วยตนเอง
3. หน้าเว็บวางเลขลงในช่องให้ตรวจสอบก่อนบันทึก โดยยังไม่ส่งข้อมูลจนกด `บันทึกแบบล็อก`
4. Server ตรวจ checksum และความซ้ำซ้อน พร้อมเข้ารหัสและบันทึกใน transaction
5. หลังสำเร็จ UI แสดงเฉพาะ `12••••••••345`; ไม่มีเส้นทางแก้ไขเลขเต็ม

> ก่อนติดตั้งจริง ให้ผู้ดูแลระบบทดสอบ Bridge บนเครื่อง Front Desk แยกจาก production และทบทวนการอนุญาต origin, การอัปเดต driver และแนวปฏิบัติจัดเก็บ log ของผู้ผลิตอุปกรณ์
